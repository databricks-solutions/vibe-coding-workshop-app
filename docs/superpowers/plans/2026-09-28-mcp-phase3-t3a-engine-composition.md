## Verified composition spec (from live TS + engine; HEAD 384ba54)

### Engine/manifest today (the substrate)
- `engine.outline(track, session)` (engine.py:91-119): status pass over `_ordered_steps` = `MANIFEST.outline_order(track, flags=_flags_for(track, session))`. **No runtime sort** — order is pure manifest declaration order minus flag-off steps.
- `outline_order(track, flags)` (manifest.py:113-127): includes each `step` unless `step.flag` is set and off. `Track.flags[name]={default, affectsSteps}`; `Step.flag: str|None` (single flag per step).
- `_flags_for` (engine.py:59-74) reads `session_parameters["flags"][name]` and top-level `session_parameters[name]`, only for names in `track.flags`.
- Manifest is GENERATED by `scripts/generate_manifest.py` (regex-parses `workflowSections.ts` + hand-maintained metadata tables); it does NOT call the TS transforms, so the 4 axes are absent today. Reverse tracks are stored FORWARD.
- Base section iteration in TS is **`WORKFLOW_SECTIONS` array declaration order** (workflowSections.ts:515-711), then reverse-sort (reverse only) then the `iterate-enhance`(998)/`cleanup`(999) tail sort. This array order — not the level's `sectionIds` order — is the byte-parity source.

### AXIS 2 — additive-chain climb → runtime chainContext input ⚠️ (NOT purely track-intrinsic)
The SAME level `lakehouse`/`lakehouse-di` yields two different outlines depending on `chainContext`:

Returns null for app-only/app-database (idx≤1) and standalone lakehouse* (chain===LAKEHOUSE_CHAIN).
- **DECISION D-T3a-2 (climb — recommend-and-proceed; the surfaced refinement of "track-intrinsic"):** the engine reads a `chainContext` input from `session_parameters` (default: the standalone/no-override behavior) and composes the climb union at runtime — parallel to how AI/medallion are session inputs. This is still engine composition; it simply cannot be a static per-track manifest order because one level has two outlines. Recommended over modeling climbed variants as distinct manifest tracks (which would explode the 14-track set and complicate the SPA/endpoint). The manifest/generator carries the chain constants + per-level sectionIds/chapterVisibility data; `outline_order` (or an engine composition step) applies the union + step-9/19 unlock. Chapter-visibility gating of steps 9/19 is SHARED machinery reverse also touches — implement it once.
