# Plan: insights-rows-reach-main (app) — PLAN ONLY, for human sign-off (D-157; must be ruled before #130 merges)

Base 99b392c. Nothing is built until the human signs.

## Problem
- #144 (`18f90ba`) and #145 (`44a5c26`) changed seed rows 300 / 1300 (insights_activation) and 305 / 1305 (insights_alerts) IN PLACE, keeping their input_ids. Rows are generated by `scripts/insights_prompts/build_rows.py`, which hard-codes `version 1, is_active true` (`build_rows.py:449`, `:460`) and allocates ids from fixed iterators (DEFAULT_IDS / FORK_IDS).
- main 2.6.0 (`24e7b99`) already installs its own original rows with the same ids. `seed_new_rows` is ON CONFLICT DO NOTHING, so an install that ran main's seed keeps main's text when it later gets the integration branch; the #144/#145 fixes never reach it. Fresh installs are fine.
- The resolver serves the highest active version per (section_tag, coding_assistant) (`routes.py:315-322`), so a NEW row with a higher version wins on every install.

## Options
- **O1 (recommended): new-version rows.**
  - Restore 300/1300/305/1305 to main 2.6.0's bytes (append-only: the ids mean the same text everywhere).
  - Emit the current integration text as new rows with new input_ids (outside the builder's existing id ranges; critic to confirm free ids), `version 2`, `is_active true`. Same pattern as D-144's row 1124.
  - Builder change: make version and id a per-row parameter (the D-150 one-line change), so the generated block holds v1 (main) + v2 (fix). `build_rows.py --check` stays the source of truth; no hand edits.
  - Effect: main installs get v2 by `seed_new_rows`; fresh installs insert both and serve v2.
- **O2: in-place update path.** Change `seed_new_rows` (or add a migration) to update rows whose bytes differ. Rejected as default: it changes seed semantics for all 185+ rows and edits learner content on live installs; it is close to the "destructive data" line the protocol parks on.
- **O3: do nothing.** Main installs serve main's original rows (missing the state handling from #145 and #144's fixes) until a manual fix. Not acceptable before #130 per D-157.
